# File Indexer

Учебный pet-проект на Java, который я делаю в первую очередь для практики многопоточности.

Идея простая: программа получает директорию, находит в ней файлы, собирает по ним информацию и постепенно превращается в небольшой файловый индексатор с очередью задач, worker-потоками, отслеживанием изменений и отдельными операциями для поиска и статистики.

Я специально не делаю проект сразу «сложным и правильным». Новые механизмы добавляются по одному, чтобы было понятно, зачем каждый из них нужен и какую проблему он решает.

## Что уже есть

Сейчас реализована базовая однопоточная часть:

- ввод директории;
- рекурсивный обход через `Files.walk()`;
- фильтрация обычных файлов;
- фильтрация по расширению;
- получение списка `Path`;
- вывод найденных файлов.

Пример:

```text
D:\Obsidian\Progaem\Кэш процессора и Java-производительность.md
D:\Obsidian\Progaem\Массивы.md
D:\Obsidian\Progaem\Многопоточность.md
D:\Obsidian\Progaem\Прерывания потоков (Thread Interruption).md
D:\Obsidian\Progaem\Пулы потоков и потокобезопасные коллекции.md
```

Следующий шаг — добавить `FileInfo` и преобразовывать найденные `Path` в объекты с метаданными файла.

## Зачем я делаю этот проект

Я изучаю многопоточность в Java и хотел сделать не набор отдельных примеров с `Thread.sleep()`, а один проект, в котором разные инструменты появляются по реальной причине.

Например:

- `BlockingQueue` — чтобы отделить поиск файлов от их обработки;
- `ConcurrentHashMap` — чтобы несколько потоков безопасно обновляли индекс;
- `AtomicInteger` / `LongAdder` — для общей статистики;
- `ThreadPoolExecutor` — для управления worker-потоками;
- `Future` — для отдельных задач поиска;
- `ReentrantLock` + `Condition` — для pause/resume;
- `ForkJoinPool` — для вычисления статистики по большому набору файлов;
- `interrupt()` и graceful shutdown — чтобы приложение корректно завершалось.

Главная цель проекта — не просто использовать эти классы, а уметь объяснить, почему в конкретном месте выбран именно этот инструмент.

## Как проект будет устроен

Планируемая схема примерно такая:

```text
                 WatchService
                      |
                      v
                  Producer
                      |
                      v
            BlockingQueue<FileTask>
                      |
          +-----------+-----------+
          |           |           |
          v           v           v
       Worker      Worker      Worker
          |           |           |
          +-----------+-----------+
                      |
                      v
          ConcurrentHashMap<Path, FileInfo>
                      |
                      v
                  File Index
```

Отдельные операции вроде полной статистики по индексу будут выполняться через `ForkJoinPool`.

## Запуск

Пока проект запускается как обычное консольное Java-приложение.

После запуска нужно передать путь к директории, например:

```text
D:\Obsidian\Progaem
```

Программа рекурсивно проходит по директории и выводит подходящие файлы.

По мере развития проекта способ запуска и доступные команды будут меняться, поэтому этот раздел тоже будет обновляться.

## Что хочу получить в итоге

Финальная версия должна уметь:

1. следить за выбранной директорией;
2. обнаруживать новые и изменённые файлы;
3. отправлять их в очередь на обработку;
4. обрабатывать несколько файлов параллельно;
5. хранить актуальный индекс;
6. показывать статистику;
7. выполнять поиск по файлам;
8. ставить обработку на паузу и продолжать её;
9. корректно завершаться даже при активных задачах.

После завершения версии на обычных platform threads хочу отдельно попробовать вариант с Virtual Threads и сравнить подходы.
